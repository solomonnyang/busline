================================================================================
BUSLINE - cPanel DEPLOYMENT GUIDE
Frontend (Vue 3 / Vite) + Backend (CodeIgniter 4) on the SAME DOMAIN
Frontend at site root, API served from https://yoursite.com/api
================================================================================

This guide assumes:
  - cPanel shared hosting, PHP 8.2+ (required by the backend).
  - You build the frontend on your local machine (cPanel has no Node.js).
  - Both apps live under public_html so a single domain serves everything.

---------------------------------------------------------------------------
PLANNED LAYOUT ON THE SERVER
---------------------------------------------------------------------------

public_html/
  .htaccess                 <-- SPA fallback + /api rewrite (you create this)
  index.html                <-- from frontend/dist
  assets/ ...               <-- from frontend/dist
  api-app/                  <-- the ENTIRE backend folder (upload it here)
    .htaccess               <-- protects app/, writable/, vendor/, .env
    app/
    writable/
    vendor/
    public/
      index.php
      .htaccess
      ...

Result:
  https://yoursite.com/          -> Vue SPA (index.html)
  https://yoursite.com/api/...   -> CodeIgniter 4 (via rewrite to api-app/public)

---------------------------------------------------------------------------
STEP 1 - BUILD THE FRONTEND LOCALLY
---------------------------------------------------------------------------

On your machine, in the `frontend/` folder:

    cd /opt/lampp/htdocs/bus/frontend
    npm install
    npm run build

Output goes to `frontend/dist/`. It contains:
  - index.html
  - assets/ (hashed .js and .css files)

NOTE: The app already calls the API with a RELATIVE path `/api`
(frontend/src/services/api.js), so NO code change is needed for same-domain
deployment. The built HTML references /assets/... from the site root, so it
must be uploaded to public_html root (not into a subfolder).

---------------------------------------------------------------------------
STEP 2 - CREATE THE DATABASE IN cPanel
---------------------------------------------------------------------------

1. Log into cPanel.
2. Open "MySQL Databases".
3. Create a database, e.g.  `yoursite_bus`.
4. Create a database user, e.g. `yoursite_bususer`, and set a strong password.
5. Add the user to the database with ALL PRIVILEGES.
6. Note the hostname: usually `localhost`. If your host requires a remote
   hostname it will be shown in cPanel; use that value in .env.

---------------------------------------------------------------------------
STEP 3 - UPLOAD THE FRONTEND
---------------------------------------------------------------------------

1. In cPanel File Manager (or FTP), go to `public_html`.
2. Delete the default `index.html` / `index.php` / `welcome` files if any.
3. Upload the CONTENTS of `frontend/dist/` directly into `public_html/`.
   Result: `public_html/index.html` and `public_html/assets/`.
   (Upload files, not the dist folder itself.)

---------------------------------------------------------------------------
STEP 4 - UPLOAD THE BACKEND
---------------------------------------------------------------------------

1. Zip the ENTIRE backend folder locally:
       cd /opt/lampp/htdocs/bus
       zip -r backend.zip backend     (Windows: right-click backend -> Send to ZIP)

   IMPORTANT: delete the local `backend/.env` before zipping OR just be
   careful not to ship real secrets; the server copy will get its own .env.
   Safest: rename it to `.env.local` before zipping, then restore after.

2. In cPanel File Manager go to `public_html`, use "Upload" to upload
   `backend.zip`.
3. Right-click `backend.zip` -> "Extract".
4. Rename the extracted folder from `backend` to `api-app`.
   Result: `public_html/api-app/`.

---------------------------------------------------------------------------
STEP 5 - CONFIGURE THE BACKEND (api-app/.env)
---------------------------------------------------------------------------

In File Manager, open `public_html/api-app/`. If there is no `.env`,
copy the `env` file and rename it to `.env`.

Edit `.env` and set (same-domain /api layout):

    CI_ENVIRONMENT = production
    app.baseURL = 'https://yoursite.com/'            # NO /api suffix, just root
    app.frontendURL = 'https://yoursite.com'
    app.forceGlobalSecureRequests = true
    app.encryptionKey = 'PASTE_A_RANDOM_32_HEX_CHARACTERS_STRING'

    database.default.hostname = localhost            # or host shown in cPanel
    database.default.database = yoursite_bus
    database.default.username = yoursite_bususer
    database.default.password = 'YOUR_DB_PASSWORD'
    database.default.DBDriver = MySQLi
    database.default.DBPrefix =
    database.default.port = 3306

    session.driver = 'database'                      # sessions table is created by migrations

    jwt.secret = 'PASTE_ANOTHER_RANDOM_LONG_STRING'
    jwt.ttl = 86400
    jwt.refresh.ttl = 604800

    paystack.secretKey = 'sk_live_...'               # or sk_test for sandbox
    paystack.publicKey = 'pk_live_...'

    email.fromEmail = 'no-reply@yoursite.com'
    email.fromName = 'BusLine'
    email.protocol = 'smtp'
    email.SMTPHost = 'smtp.yourhost.com'
    email.SMTPUser = 'your SMTP user'
    email.SMTPPass = 'your SMTP password'
    email.SMTPPort = 465
    email.SMTPCrypto = 'ssl'                         # or tls / leave empty
    email.SMTPAuthMethod = 'login'
    email.SMTPTimeout = 10

    cors.allowedOrigins = 'https://yoursite.com'     # same-origin, but harmless

Generate a fresh encryption key (32 hex chars), e.g.:
    php -r "echo bin2hex(random_bytes(16));"

Generate a fresh JWT secret, e.g.:
    php -r "echo bin2hex(random_bytes(32));"

--------------------------------------------------------------------------------
STEP 6 - CREATE THE ROOT .htaccess (public_html/.htaccess)
--------------------------------------------------------------------------------

Create `public_html/.htaccess` with EXACTLY this content:

    <IfModule mod_rewrite.c>
        RewriteEngine On

        # --- 1) Route /api/* to the CodeIgniter backend -----------------------
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteRule ^api/?(.*)$ api-app/public/index.php [L,QSA]

        # --- 2) Pass the Authorization header (JWT) ---------------------------
        RewriteCond %{HTTP:Authorization} .
        RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]

        # --- 3) SPA fallback: any non-file/non-dir route -> index.html --------
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteCond %{REQUEST_FILENAME} !-d
        RewriteRule ^ index.html [L]

        # --- 4) Force HTTPS ---------------------------------------------------
        RewriteCond %{HTTPS} off
        RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
    </IfModule>

    # --- 5) Security headers + Content-Security-Policy ----------------------
    <IfModule mod_headers.c>
        Header set X-Content-Type-Options "nosniff"
        Header set X-Frame-Options "DENY"
        Header set Referrer-Policy "strict-origin-when-cross-origin"
        Header set Permissions-Policy "camera=(self), microphone=(self), geolocation=(self)"
        Header set Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com data:; img-src 'self' data: https://tile.openstreetmap.org https://*.tile.openstreetmap.org; connect-src 'self' https://nominatim.openstreetmap.org https://router.project-osrm.org; base-uri 'self'; form-action 'self'; frame-ancestors 'none'"
    </IfModule>

WHY IT WORKS:
  - The rewrite to `api-app/public/index.php` keeps the original REQUEST_URI
    (/api/login, /api/trips, ...) intact, so CodeIgniter's routes (all grouped
    under `api`) match exactly. No baseURL subpath tricks needed.
  - Everything else falls back to index.html so vue-router's history mode
    (frontend/src/router/index.js, createWebHistory) works on deep links like
    /customer/dashboard.

--------------------------------------------------------------------------------
STEP 7 - PROTECT THE BACKEND FOLDER (public_html/api-app/.htaccess)
--------------------------------------------------------------------------------

Create `public_html/api-app/.htaccess` with this content to block direct web
access to sensitive backend folders and files (only public/ is reachable via
the rewrite):

    <IfModule mod_rewrite.c>
        RewriteEngine On
        RewriteRule ^app(/|$) - [F,L]
        RewriteRule ^writable(/|$) - [F,L]
        RewriteRule ^vendor(/|$) - [F,L]
        RewriteRule ^system(/|$) - [F,L]
        RewriteRule ^\.env$ - [F,L]
        RewriteRule ^\.git(/|$) - [F,L]
    </IfModule>
    Options -Indexes

--------------------------------------------------------------------------------
STEP 8 - SET WRITABLE PERMISSIONS
--------------------------------------------------------------------------------

The backend writes to `public_html/api-app/writable/` (cache, logs, session,
uploads, qr). In File Manager, select these folders and set permissions to
755 (or 775 if your host uses a different group):
    - writable/
    - writable/cache/
    - writable/logs/
    - writable/session/
    - writable/uploads/
    - writable/qr/

--------------------------------------------------------------------------------
STEP 9 - RUN MIGRATIONS AND SEEDERS
--------------------------------------------------------------------------------

Migrations create all tables; seeders insert roles, the admin user, cities,
terminals, the bus catalog, offers and settings.

Option A - cPanel Terminal (recommended, no SSH key needed):
  1. In cPanel open "Terminal" (hosting must allow it).
  2. cd to the backend and run:

        cd ~/public_html/api-app
        php spark migrate

        php spark db:seed --class=RoleSeeder
        php spark db:seed --class=AdminSeeder
        php spark db:seed --class=CitySeeder
        php spark db:seed --class=TerminalSeeder
        php spark db:seed --class=BusCatalogSeeder
        php spark db:seed --class=VendorFleetSeeder
        php spark db:seed --class=OfferSeeder
        php spark db:seed --class=SettingSeeder

Option B - If no Terminal, use the web installer (being built) which performs
the same migrate + seed steps from a browser page.

The AdminSeeder creates the default super admin login (see
app/Database/Seeds/AdminSeeder.php). CHANGE THOSE CREDENTIALS or delete the
seed after first login.

--------------------------------------------------------------------------------
STEP 10 - SET PHP VERSION (cPanel MultiPHP)
--------------------------------------------------------------------------------

1. In cPanel open "Select PHP Version" (MultiPHP Manager).
2. For the domain, select PHP 8.2 or newer (e.g. 8.3).
3. Enable required extensions: mysqli, pdo_mysql, openssl, curl, mbstring,
   intl, gd (QR codes), zip, json.
4. In php.ini settings set:
       upload_max_filesize = 8M
       post_max_size = 8M
       max_execution_time = 300
       memory_limit = 256M

--------------------------------------------------------------------------------
STEP 11 - SSL / HTTPS
--------------------------------------------------------------------------------

1. In cPanel open "SSL/TLS Status" or "Let's Encrypt" and issue an SSL cert
   for yoursite.com (and www). Force HTTPS is already handled by the root
   .htaccess from Step 6.
2. app.forceGlobalSecureRequests = true (set in Step 5) makes the backend
   reject plain-HTTP requests.

--------------------------------------------------------------------------------
STEP 12 - TEST
--------------------------------------------------------------------------------

1. Open https://yoursite.com/        -> you should see the Vue app.
2. Register a customer at https://yoursite.com/register.
3. Test a public API directly in the browser:
       https://yoursite.com/api/cities      -> JSON list of cities
4. Log in at https://yoursite.com/login -> you should land in the dashboard.
5. Refresh a deep link like https://yoursite.com/customer/dashboard -> it must
   load the SPA (not 404) thanks to the fallback rule.

--------------------------------------------------------------------------------
TROUBLESHOOTING
--------------------------------------------------------------------------------

- Blank page on /api/*          -> Check .env DB credentials; check writable/
   permissions; check PHP version is 8.2+; check backend error log at
   api-app/writable/logs/.
- /api returns 404               -> Root .htaccess not applied (rules order) or
   api-app path wrong; confirm rewrite rule targets api-app/public/index.php.
- SPA deep link 404s             -> The SPA fallback rule must come AFTER the
   api rewrite and must not intercept /api.
- Auth "Unauthorized" on API     -> The HTTP_AUTHORIZATION passthrough rule is
   missing from the root .htaccess (Step 6, rule 2).
- 500 with "paths" error         -> You uploaded backend to a different folder
   depth; index.php uses __DIR__.'/../app/Config/Paths.php' and Paths.php uses
   __DIR__.'/../../vendor/...' so the folder layout must stay exactly as in
   Step 4.
- Login fails, "database" session errors -> Run migrations (Step 9); the
   sessions table only exists after migrate.

--------------------------------------------------------------------------------
NOTES
--------------------------------------------------------------------------------
- The frontend is built once locally and uploaded; rebuild + re-upload
  `dist/` whenever you change frontend code.
- Never upload `backend/.env` with real secrets; the server copy is separate.
- Paystack webhooks must point at (POST):
       https://yoursite.com/api/paystack/webhook
  The endpoint verifies the HMAC-SHA-512 signature against your Paystack
  secret before confirming bookings or crediting wallets. Scopes: charge.success.
